                  Audit Enforcement Points for Agents
               draft-liu-audit-enforcement-points-latest

Abstract

   This document identifies key audit enforcement points for agents,
   specifying the calls they cover and the audit records they provide.
   It also describes the hooks used to capture these records and how
   hook failures are handled.

1.  Introduction

   Agents are increasingly acting on behalf of users across multiple
   services and administrative domains.  Their activities may involve
   the original user, other agents, models, tools, and hosts.
   Information about these activities is distributed across
   participants, with no single party observing the entire interaction
   chain.  AUDIT therefore aims to enable the collection and correlation
   of this information to provide visibility across the chain.

   Security products and components deployed along the interaction chain
   can provide audit information by inspecting requests, enforcing
   access decisions, and monitoring execution.  For example, agent
   gateways can observe requests from users, applications, or other
   agents and the corresponding responses; model gateways can inspect
   model requests, context, and responses; MCP proxies can inspect tool
   calls and results; and EDR systems and sandbox monitoring components
   can capture host operations such as process creation, file access,
   and network connections.  These products and components serve as
   audit enforcement points, each covering a different part of agent
   activity.

   To use this information for auditing, it is necessary to understand
   which calls and operations each enforcement point covers and what
   audit information it can provide.  This document classifies audit
   enforcement points into three categories based on the calls they
   cover: agent interaction, model and tool invocation, and host-level
   operation.  For each category, It describes the audit information
   available through hooks at each enforcement point and how hook
   failures are handled.  This analysis provides a basis for identifying
   a minimum necessary set of audit records.
